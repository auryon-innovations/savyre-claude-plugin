# Run Stage

## Role and inputs
Read `references/runtime-boundary.md` before work and `references/invocation-map.md` when selecting a pass or returning to its primary. This reusable consumer is not the active primary stage, an approval authority or a missing runtime producer. In managed mode use only assigned compatible context; in explicitly requested preview label proposed outputs unbound.

Inputs: Actual status/context, stage/internal step, compatible registered bundle entries, allowed actions/writer delegation and resume/next-action records.

## Procedure

1. Read references/invocation-map.md and verify active managed identities/status. Idle/missing/incompatible context means report diagnostic and stop managed dispatch; explicit preview only describes mapping/draft limitations.
2. Resolve the assigned S01–S07 primary from registered packages; dispatch dedicated challenge/grounding only when runtime assigns it. Cross-stage shared consumers ride alongside primary, not replace activeSkill.
3. Require available compatible package/version and allowed delegated action; no fake invocation, unavailable subagent or hidden legacy renumber. Missing dedicated pass needs diagnostic or explicit runtime fallback.
4. Return selected primary/pass and its input/writer/permission bindings to existing runtime. Do not recursively call router from primary or run lock/approve/unlock/merge/deploy actions.

## Output and handoff
Selected stage/primary/pass names, available compatibility refs, permission/writer boundary and actual diagnostic/next action.

Artifact ownership: Dispatcher/selection response only; runtime owns invocation and transitions.

Return to the assigned primary/runtime without recursively dispatching yourself or pretending an unavailable role/tool ran. Preserve developer feedback and canonical state. A clean analysis is advisory; current runtime permits/completes actions.
